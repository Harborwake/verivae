# Verivae Docs

This folder contains the planning documents Codex should read before building Verivae.

## Recommended Reading Order

1. [Verivae Codex Kickoff Prompt](Codex-Kickoff-Prompt.md)

   This is the exact prompt to use when starting the first real Codex build task.

2. [Verivae App Design Brief](Verivae-App-Design-Brief.md)

   This is the full product design reference exported from Google Docs. It explains the larger app vision, capabilities, screens, safety behavior, privacy behavior, recovery behavior, and future feature direction.

3. [Verivae Codex Build Handoff - MVP 1](Verivae-Codex-Build-Handoff-MVP-1.md)

   This is the main starting document for Codex. It explains what the first useful version should include, what should stay out of MVP 1, and how the app should keep scam-checking logic reusable for future mobile, browser-extension, and desktop experiences.

4. [Verivae Product Safety Boundaries](Product-Safety-Boundaries.md)

   This explains what Verivae may safely claim, what it must avoid promising, and how the app should handle scams, money, recovery, privacy, device safety, and uncertainty.

5. [Verivae MVP Feature Checklist](MVP-Feature-Checklist.md)

   This is the beginner-friendly task checklist for the first build. It matches the GitHub Issues used to organize MVP work.

6. [Verivae Architecture Notes](Architecture-Notes.md)

   This explains how Codex should keep the first build organized so future mobile, browser-extension, and desktop work can reuse the same scam-checking foundation.

## Build Rule

Codex should build the smallest useful version first. Future features such as Gmail review, text-message review, QR scanning, attachment review, device checks, weekly deep checks, paid plans, browser-extension protection, and deeper recovery tools should stay in backlog until the manual scam-check MVP works well.
